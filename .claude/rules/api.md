# 서비스 API 규칙 (저장 없음)

- 서버는 이야기를 저장하지 않는다. 구간마다 HMAC 서명을 붙여 돌려주고, 프론트가 다음 요청에 지난 구간 전체를 서명과 함께 보낸다.
  - 왜: DB 없이 마감(11/3)을 맞추기로 함(2026-10-29). 책장·이어하기는 프론트 IndexedDB.
  - 서명에는 story(id·카드·선택 횟수·목소리)·index·구간이 함께 들어간다. 본문을 고치면 400 `bad_signature` → 자유 입력(프롬프트 주입) 차단.
  - `STORY_SECRET` 은 32자 이상. 바꾸면 진행 중인 이야기는 이어지지 않는다.
- 한도는 서버 메모리에서 센다(재시작하면 0). 실제 한도는 Gemini·Typecast 가 막으므로 넘쳐도 과금은 없고 그 구간이 글만 나온다.
  - 이야기 수: 익명 ID당·전체 하루(KST). 같은 구간 다음 요청은 2번까지(반복 요청으로 LLM 한도 소진 방지).
  - Gemini TTS: 모델마다 하루 10회, **태평양 시간 자정** 초기화(KST 16~17시). 이야기 시작 때 구간 수만큼 예약, 예약을 넘는 호출(재시도·두 번째 요청)은 사용량에 더한다.
  - TTS 429·402 는 같은 모델로 다시 부르지 않는다(바로 불러도 실패하고 한도만 씀).
  - 정해진 모델이 실패하면 **같은 목소리 이름**으로 한도가 남은 다른 Gemini 모델을 1번씩(처음 모델만 1번 다시 시도, 최대 약 75초, 화면은 90초 대기). Azure 등 다른 목소리로는 넘어가지 않는다(사용자 결정).
  - Google 이 하루 한도 429 를 주면 그 모델을 오늘 다 쓴 것으로 기억(`mark_gemini_used_up`). 서버를 다시 켜면 메모리 계산이 0부터라 실제 사용량과 어긋났다(2026-10-30, 실험 중 실패가 잦았던 원인).
  - 실패 로그 `tts_failed` 에 Google 오류 내용(어떤 한도인지)을 남긴다. 화면은 못 받거나 재생이 막히면 `voice_failed` 이벤트.
  - 하루 한도 구분은 오류 본문의 `per_day` 로 판단한다(실제 문구는 아직 확인 못 함).
- TTS 연출 지시(`tts/gemini.py` 의 `DIRECTION`): 'DIRECTOR'S NOTES / TRANSCRIPT' 형식, 조금 느리게·생기 있게.
  - 겪은 문제: 한 문장 지시를 3.x 모델이 소리 내어 읽었다. 이 형식으로 바꾼 뒤에도 3.8 은 짧은 글(20자)에서 지시까지 읽어 25초가 나왔다(2026-10-30).
  - 안전장치: 음성이 `2초 + 글자당 0.27초`보다 길면 `too_long` 실패로 보고 다음 모델로 넘긴다(`tts_service.py`). 보통은 글자당 약 0.19초. 300자 넘는 구간은 놓칠 수 있다.
  - 다음 할 일: 3.8 용 지시 형식을 따로 시험(한도가 차는 KST 16~17시 이후).
- 음성 끝: 서버가 끝 0.15초를 줄이고 0.3초 무음을 붙인다(`audio.py` 의 `soften_end`). 화면도 끝 0.8초 전부터 줄이고 0.3초 전에 멈춘다(끝의 '콱' 소리).
- 시연용 ElevenLabs(`tts/elevenlabs.py`): 키와 `ELEVENLABS_VOICE_ID`(·`_2`)가 있으면 `/api/voices` 가 번호(eleven1·2)와 이름을 돌려주고, 설정 창에서 고른 사람만 그 목소리. 목소리 ID 는 화면에 보내지 않는다. 미리 듣기 파일은 `tools/voice_preview.py` 로 한 번 만든다. PCM 24kHz 로 받아 Gemini 와 같은 길이 검사·끝 처리.
  - 유료 크레딧이라 하루 글자 수 상한(기본 10,000자)을 메모리에서 센다. 넘으면 그 이야기부터 Gemini.
  - 실패해도 Gemini 로 넘어가지 않는다(중간에 목소리가 확 달라짐) → 그 구간은 글만. 401(크레딧 소진)은 다시 시도하지 않는다.
  - 2026-10-30 사용자 키는 TTS 권한만 있어 요금제·목소리 목록 조회(401 missing_permissions)는 안 된다.
- 이야기 목소리: 시작 요청의 `voice`(Kore·Aoede·Leda, 설정에서 고름)를 쓰고, 없으면 무작위. Typecast 로 넘어가면 쓰지 않는다.
- `/api/speak`: 안내·질문·선택지(200자 이하)를 Azure(무료 F0, 여성 SunHi·남성 InJoon)로 읽는다. 하루 15,000자, 키가 없으면 503 → 화면이 브라우저 음성으로.
- LLM: 기본(3.5 Flash Lite)·예비(3.1 Flash Lite)를 **동시에** 불러 먼저 검사를 통과한 글을 쓴다. 모두 Google 모델이라 키는 `GEMINI_API_KEY` 하나.
  - 왜: 기본만 쓸 때 구간당 10~25초(목표 10초). 하루 30편 상한이면 모델당 하루 150회 정도라 무료 한도(500회) 안.
  - 쓰지 않은 모델도 끝나는 대로 `segment_unused` 로그(모델·성공·걸린 시간)를 남긴다 → 모델 속도 비교.
  - 대비 모델(`BACKUP_MODELS`, Gemma)은 기본 꺼 둠. 응답이 60초를 자주 넘고 들쭉날쭉했다.
- 기록은 DB 대신 `log_event` 로 JSON 한 줄(Cloud Run 로그). API 키·서명 비밀값은 넣지 않는다(`test_log_has_no_secret`).
- `.env` 의 JSON 목록(`BACKUP_MODELS`, `CORS_ORIGINS`)은 작은따옴표로 감싼다.
  - 겪은 버그: `uv run --env-file` 이 큰따옴표를 지워 `["a"]` → `[a]` 가 되어 서버가 시작하지 않았다.
- 빈 주소 줄(`PRIMARY_BASE_URL=`)은 기본 주소(Gemini)로 처리한다. 예전 `.env.example` 을 복사한 `.env` 에 남아 있었다.
- Windows 콘솔에서는 로그의 한글이 깨져 보인다(cp949). Cloud Run(Linux)에서는 UTF-8.
