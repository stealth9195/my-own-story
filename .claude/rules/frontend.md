# 화면 규칙

- 사용자는 React 를 이번에 처음 배운다. React 코드에는 처음 나오는 개념(훅, 상태 등)을 짧게 설명한다.
- 화면을 바꾸면 **모바일 폭(375px)에서 가로 넘침이 없는지** 확인한다.
- 휴대폰 실제 확인은 같은 와이파이에서 `--host` 로 띄운 주소로.
- 아이폰(Safari/WebKit)은 따로 의심한다.
  - 사용자가 화면을 터치하기 전에는 소리(TTS·효과음·음악)를 자동 재생하지 않는다. 첫 재생은 버튼 터치에서 시작한다.
  - PWA 캐시 동작이 Chrome 과 다르다.
- 아이가 혼자 조작할 수 있게 버튼은 크게, 글보다 그림 위주로.

## 구조 (3차)

- 라우터 없이 `App.tsx` 의 `screen` 하나로 화면 전환: home → pick → waiting → reading ↔ shelf, 오류는 problem.
- 서버는 저장하지 않는다. 이야기(서명된 구간)·음성(MP3)은 `storage.ts`(idb-keyval, IndexedDB). 음성은 최근 20편만.
  - 저장 오류는 모두 무시한다(사파리 비공개 모드 등에서도 이야기는 진행). `storage.noidb.test.ts` 로 확인.
- 계산은 `story.ts` 의 순수 함수(다음 요청, 페이지 시간, 조사 은/는·이/가)로 빼서 Vitest 로 테스트한다. 화면은 브라우저로 확인.
- 그림 에셋 전까지 카드·장면은 `shared/catalog.json` 의 `emoji`. 배경은 색(`.scene.bg-<id>`).

## 소리

- 첫 터치("새 이야기 만들기", 책장 열기)에서 `unlockAudio()` → 이후 이야기 음성은 `audio.player` 하나로 재생(아이폰).
- 이야기 본문: 서버 구간 음성(MP3). 페이지는 글자 수 비율로 자동 넘김. 음성이 오기 전엔 다음 장 잠금, 실패하면 "다음 ▶" 버튼.
- 질문·선택지·안내: 브라우저 `speechSynthesis`(무료). 서버 TTS 하루 한도(모델당 10회)를 본문에만 쓰기 위해.
- 늦게 도착한 음성은 재생 순번(`playToken`/`isCurrent`)으로 막는다. 화면을 떠나면 `stopAll()`.
- 겪은 문제: 개발 모드(React StrictMode)는 화면 준비(useEffect)를 두 번 실행한다.
  - 그대로 두면 구간 음성·다음 구간을 두 번 요청해 서버 한도(구간당 2번)를 헛되이 쓴다.
  - 그래서 음성 요청은 `audioRequests` 로 묶고, 다음 구간 요청은 `requesting` 으로 막는다. 이어하기 표시는 effect 안에서 끄지 않는다.
- 선택은 두 번 누르기: 첫 터치는 이름 읽기, 같은 카드를 한 번 더 누르면 고름(글 못 읽는 아이용).
