# 화면 규칙

- 사용자는 React 를 이번에 처음 배운다. React 코드에는 처음 나오는 개념(훅, 상태 등)을 짧게 설명한다.
- 화면을 바꾸면 **모바일 폭(375px)에서 가로 넘침이 없는지** 확인한다.
- 휴대폰 실제 확인은 같은 와이파이에서 `--host` 로 띄운 주소로.
- 아이폰(Safari/WebKit)은 따로 의심한다.
  - 사용자가 화면을 터치하기 전에는 소리(TTS·효과음·음악)를 자동 재생하지 않는다. 첫 재생은 버튼 터치에서 시작한다.
  - PWA 캐시 동작이 Chrome 과 다르다.
- 아이가 혼자 조작할 수 있게 버튼은 크게, 글보다 그림 위주로.

## 구조 (3차)

- 라우터 없이 `App.tsx` 의 `screen` 하나로 화면 전환: home → pick → waiting → reading ↔ shelf, 오류는 problem.
- 서버는 저장하지 않는다. 이야기(서명된 구간)·음성(MP3)은 `storage.ts`(idb-keyval, IndexedDB). 음성은 최근 20편만.
  - 저장 오류는 모두 무시한다(사파리 비공개 모드 등에서도 이야기는 진행). `storage.noidb.test.ts` 로 확인.
- 계산은 `story.ts` 의 순수 함수(다음 요청, 페이지 시간, 조사 은/는·이/가)로 빼서 Vitest 로 테스트한다. 화면은 브라우저로 확인.
- 그림은 `public/img/{id}.webp`, 없으면 이모지(`Picture`). 장면은 `Scene`(배경·시간대 색·배치·상태 표시).

## 읽기 화면 (4차)

- 읽기 화면은 화면 높이에 맞추고 글 칸만 스크롤 → 이전/다음·선택지는 늘 글 칸 아래 같은 자리.
- 읽은 쪽 글은 지우지 않고 아래로 이어 붙인다(지난 쪽은 흐리게, 새 쪽은 점점 진해짐).
- 다음 구간을 만드는 동안 화면을 바꾸지 않고 장면 위에 '만들고 있어요' 덮개(아이가 당황하지 않게).
- 다 만든 이야기: 듣던 위치를 `position.ts`(localStorage) 에 저장 → '이어 듣기 / 처음부터', 다시 들을 때 ◀ 이전 / 다음 ▶.
- 위쪽: 🏠, 쪽수, ⏸️(재생 중), 🎵 음소거, ⚙️ 설정(음악·목소리 크기, 배속 0.8~1.3, 이야기 목소리 미리 듣기, 안내 목소리).
- 겪은 버그: 구간이 바뀐 직후 이전 구간의 페이지 번호로 한 번 그려져, 새 구간이 더 짧으면 없는 페이지를 읽다 화면 전체가 하얗게 멈췄다 → 마지막 쪽을 넘지 않게(`shown`).
- 겪은 버그(2026-10-31 배포판): 서버가 쪽이 0개인 구간을 보내 `shown` 이 비어 화면이 하얗게 멈췄다. 서버는 이제 거절하지만, 이미 책장에 저장된 이야기에 남아 있을 수 있어 화면에서도 `shown` 이 없으면 오류 화면('처음으로'만)을 보여 준다.
  - 배포판 오류 위치 찾기: 콘솔의 `index-xxxx.js:줄:칸` 을 배포 주소의 `/assets/` 파일에서 그 칸 앞뒤로 잘라 보면 어느 코드인지 알 수 있다(소스맵 없음).
- 개발 중 확인 화면: `npm run dev` 에서 `?demo`(장면 비교·링크 모음), `?demo=reading`(읽기 화면, 저장소·서버 없이),
  `?demo=reading-turn`(3쪽, 책장 넘김), `?demo=waiting`(기다림), `?demo=problem`·`problem-limit`(오류). 배포판에서는 꺼짐.
  - `?demo=reading` 에서 선택지를 두 번 누르면 가짜 이야기(`story:demo-reading`, 1970년 날짜)가 책장에 저장된다. 이어하기를 누르면 서명이 가짜라 서버가 거절해 오류 화면이 나오는 게 정상 → 책장에서 지운다.

## 디자인 (5차, 2026-10-31)

- 시안: OpenDesign 스타일 타일 A안 '크레파스 손그림 + 진짜 그림책'. 시연을 **PC 로 하므로 PC(≥1024px) 우선**, 폰은 큰 오류만 없게.
  - 왜: 발표 시연이 PC(노트북·프로젝터). 1440×900 과 1280×720(프로젝터) 둘 다 한 화면에 들어가는지 확인한다.
- 색·모양·간격은 `index.css` 의 `:root` 변수(`--bg`, `--accent`, `--wobble-a` 등). 버튼 클래스는 예전 이름 그대로(`big-button`, `icon-button`).
- 글꼴: 제목·버튼 Jua(Google Fonts), 본문 Pretendard(jsDelivr) — `index.html` 에서 불러온다. 인터넷이 없으면 기본 글꼴로 보인다.
- PC 는 화면마다 **펼친 그림책**: 책 종이는 `::before`, 가운데 책등 그림자는 `::after`(`--spine`), 왼쪽 쪽 그림·오른쪽 쪽 글/버튼.
  - 레이아웃은 `@media (min-width: 1024px)`. 폰 가로 읽기 화면은 `(orientation: landscape) and (max-width: 1023px)` — PC 도 가로라서 범위를 꼭 나눈다.
- 책장 넘김(PC 읽기 화면, `Reading.tsx` 의 `turn`): 다음 = 오른쪽 글 쪽이 책등을 축으로 왼쪽으로, 이전(다시 듣기 ◀) = 왼쪽 장면 쪽이 오른쪽으로.
  - 장면 반쪽이 아니라 쪽 전체를 넘긴다(펼친 책이라 실제 그림책에 가까움, 사용자 결정). 0.65초(`--turn-dur`), transform 만 움직인다.
  - 넘기는 동안 화면에는 이전 장면/글을 두고, 넘김이 끝나면(`animationend`) 지운다. 폰·움직임 줄이기에서는 넘기지 않는다.
  - 구간이 바뀐 직후 쪽 번호가 잠깐 예전 값이라, 넘김 시작 0.3초 안의 쪽 번호 변화는 새 넘김으로 치지 않는다.
- 겪은 버그: 책장에서 다시 들을 때 '다음'을 누르면 넘김이 두 번 나왔다.
  - 원인은 쪽 번호가 2→1→2 로 잠깐 되돌아감. MP3 는 `currentTime` 을 정확히 못 옮기고 살짝 앞에 멈춰, 그 위치가 앞 쪽으로 계산됐다.
  - 0.05초 뒤로 옮기고, 길이를 알기 전·이동 중(`seeking`) 재생 위치 알림은 무시한다. 넘김 전에도 있던 버그(글이 한 번 깜빡임).
- 이름 겹침 주의: CSS 는 전역이라 `.actor`(장면) 같은 이름을 다른 화면에서 쓰면 깨진다(홈 그림이 어긋났음) → 화면 접두어(`home-`, `pick-`, `wait-`, `book-`).
- `Picture` 의 그림은 칸을 채우며 비율을 지킨다(`object-fit: contain`) → 바깥 칸 크기만 정한다. 퍼센트 높이가 안 먹는 칸(격자 auto 줄)에서는 `position: absolute` 로 크기를 준다.

## 책장 (5차)

- PC: 크레파스 책장(한 칸 4권, 책이 많으면 책장 안 스크롤). 책은 앞표지 ← 상아색 종이(줄 없음) ← 뒷표지로 두께. 표지 색은 빨·파·초·노 차례.
  - 종이 줄은 방향 맞춘 줄·낙서 줄과 비교 후 '줄 없음'으로 결정(실제 크기에서 줄이 지저분하거나 안 보임).
- 책을 누르면 창: 다 들은 이야기는 '다시 듣기'(결말 화면 없이 바로 처음부터, `Reading` 의 `startOver`), 만드는 중이면 '이어하기', 그리고 '지우기'.
  - 지우기는 '정말 지울까요?'를 한 번 더 묻고 이야기·음성(`deleteStory`)·듣던 위치(`clearPosition`)까지 지운다.
- 표지 왼쪽 위 하트: 좋아하는 이야기 표시(`SavedStory.favorite`). 버튼 안에 버튼을 둘 수 없어 책과 하트를 `.book-wrap` 에 나란히 둔다.

## 소리

- 첫 터치("새 이야기 만들기", 책장 열기)에서 `unlockAudio()` → 이후 이야기 음성은 `audio.player` 하나로 재생(아이폰).
- 이야기 본문: 서버 구간 음성(MP3). 페이지는 글자 수 비율로 자동 넘김. 음성이 오기 전엔 다음 장 잠금, 실패하면 "다음 ▶" 버튼.
  - 음성이 60초(`SLOW_VOICE_MS`) 넘게 늦으면 "다음 ▶" 버튼으로 먼저 넘길 수 있다. 음성은 계속 받아 오면 넘긴 쪽부터, 이미 선택지까지 넘겼으면 들려주지 않는다(사용자 요청 2026-10-31).
- 질문·선택지·안내: Azure 안내 목소리(`/api/speak`, 설정에서 여성·남성). 같은 글은 한 번만 받아 둔다. 실패하면 브라우저 `speechSynthesis`.
  - 왜: 브라우저 음성은 기계음이라 듣기 힘들다는 의견(2026-10-30). 서버 Gemini TTS 하루 한도는 본문에만 쓴다.
- 선택지는 자동으로 읽지 않고, 아이가 한 번 눌렀을 때만 그 이름을 읽는다(어차피 두 번 눌러야 고름).
- 이야기 음성 끝: 끝나기 0.8초 전부터 줄이고 0.3초 전에 멈춘다(`audio.ts` 의 `watchEnd`).
  - 끝의 짧고 큰 '콱' 소리는 화면 문제가 아니라 파일 자체에 있었다(서버 `gemini.py` 의 `_to_wav` 로 해결). 소리 문제는 먼저 저장된 MP3 를 받아 파형을 본다.
- 효과음은 페이지가 바뀌고 2초 뒤(`sound.ts` 의 `SFX_DELAY_MS`), 그 사이 페이지가 바뀌면 취소.
- 늦게 도착한 음성은 재생 순번(`playToken`/`isCurrent`)으로 막는다. 화면을 떠나면 `stopAll()`.
- 겪은 문제: 개발 모드(React StrictMode)는 화면 준비(useEffect)를 두 번 실행한다.
  - 그대로 두면 구간 음성·다음 구간을 두 번 요청해 서버 한도(구간당 2번)를 헛되이 쓴다.
  - 그래서 음성 요청은 `audioRequests` 로 묶고, 다음 구간 요청은 `requesting` 으로 막는다. 이어하기 표시는 effect 안에서 끄지 않는다.
- 선택은 두 번 누르기: 첫 터치는 이름 읽기, 같은 카드를 한 번 더 누르면 고름(글 못 읽는 아이용).
- 아이폰(Safari)은 `audio.volume` 을 무시한다(2026-10-31 실제 확인): 설정의 음악·목소리 크기, 음성 중 음악 줄이기, 끝 줄이기가 안 된다. 시연이 아이폰이 아니라 고치지 않기로 함. 고치려면 Web Audio(`GainNode`)로 바꿔야 한다.
