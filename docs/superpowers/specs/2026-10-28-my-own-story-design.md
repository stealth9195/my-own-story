# my-own-story 기획안

- 작성일: 2026-10-28
- 프로젝트명: `my-own-story` (임시, 이름 후보 미정)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스 | 취향 카드와 선택지로 이어가는 AI 구연동화 웹앱 |
| 대상 | 4~7세 (초1까지 허용). 주 사용 방식은 부모 동반, 아이 혼자서도 조작 가능 |
| 목적 | 포트폴리오. 무료 공개 후 실사용 기록 확보 → 문제 해결 경험 정리 |
| 운영 원칙 | 운영비 0원 (무료 티어만 사용) |
| 우선순위 | 빠른 완성 + 완성도 |

**문제 정의**
- 부모가 바쁘거나 목이 아파서 매번 읽어주기 어려움
- 같은 책을 반복해서 읽으면 아이가 지루해함. 새 책 구입은 부담

**해결 방향**
- TTS가 실감 나게 읽어줘서 부모 부담을 줄이고 몰입도를 높임
- 아이가 이야기 방향을 직접 골라 매번 새 이야기 → 창의성·상상력, 읽는 즐거움

## 2. 확정 결정

| 항목 | 결정 |
|---|---|
| 형태 | PWA로 시작 → 반응 좋으면 네이티브 확장 |
| 로그인 | MVP 없음. 기기별 익명 ID. 이후 구글 로그인 추가 |
| 이야기 생성 | 매 구간 LLM 실시간 생성 |
| 그림 | 미리 만든 조각을 조립 + CSS 반복 애니메이션. 결말 그림 AI 생성은 MVP 이후 실험 |
| 음성 | Gemini TTS (구간 단위 생성) + 음성 캐싱. Gemini 한도 초과 시 Typecast, 그것도 부족하면 브라우저 TTS. 한 이야기 안에서 목소리 고정 |
| 효과음·음악 | 미리 준비한 목록에서 LLM이 ID로 선택. MVP 포함 |
| 그림·소리 매칭 | 임베딩 없음. 프롬프트에 목록을 넣고 ID만 출력하게 강제 |
| 스택 | React(Vite, TypeScript) + FastAPI + Supabase |
| 배포 | 프론트: Cloudflare Pages 또는 Vercel / 백엔드: Google Cloud Run / DB·Storage: Supabase |

## 3. 이야기 구성 (프롬프트 v8 기준, 2026-10-29 갱신)

| 구간 | 플롯 단계 | 분량 | 끝맺음 |
|---|---|---|---|
| 발단 | 발단 | 3페이지 | 다음 선택을 유도하는 문장 (예: "눈앞에 뭔가 나타났어요. 그건 바로...", "그 집의 생김새는...") |
| 중간 (×3) | 전개 · 위기 · 절정 | 각 2~3페이지 | 동일 |
| 결말 | 결말 | 3페이지 | 자연스러운 마무리, 따뜻한 결말 |

- 플롯: 발단 → 전개 → 위기 → 절정 → 결말. 4~7세용이라 위기·절정도 무섭지 않게. 구간 수가 적으면 단계를 합침 (예: 4구간 = 발단, 전개, 위기·절정, 결말)
- 페이지: 딱 2문장, 약 40~70자 (검증 상한 150자)
- 합계: 약 11~15페이지, 600~1,000자
- 선택 횟수: 설정값 (기본 4, 범위 2~5). 발단 끝 1번 + 중간 구간 끝마다 1번
- 구간 수: 발단 1 + 중간 (선택 횟수 - 1) + 결말 1. 기본값이면 중간 3구간 (5단계 플롯과 일치)
- LLM 호출: 1편당 선택 횟수 + 1회 (기본 5회)
- 선택지: 구간마다 3개. 한 구간 안에서는 한 종류만
  - 물건형: 다음에 나타날 캐릭터·사물 (그림 있음). 구성 = 고른 카드와 관련 / 엉뚱한 것 / 흐름에 맞는 것. 에셋 목록 중 카드·이미 나온 것·이미 등장한 것을 뺀 후보에서만
  - 문장형: 마지막 문장을 이어서 끝내는 짧은 말 (예: "아주 커다랬어요!"). 20자 이하, 그림 없음
  - 끝맺음 종류는 코드가 정함: 결말 직전은 물건형, 같은 종류 3번 연속 금지, 나머지는 무작위
- 고른 선택지는 다음 구간 첫 페이지에 등장하고 이야기의 중심이 됨. 고르지 않은 선택지는 등장하지 않음
- 발단 첫 페이지에 주인공 필수. 처음 고른 사물·장소도 발단 안에 등장
- 장면 정보(`scene`)에는 주인공·사물·장소만. 성격·상황은 본문에만 반영
- 세부 문구는 `prompts/v8/` 참고

## 4. MVP 범위

**포함**
- 처음 선택 4단계: 주인공(캐릭터 5장 중 1) → 성격(4개 중 1) → 배경(장소·상황 4개 중 1) → 사물(4개 중 1). 후보는 매번 전체 목록에서 무작위
- 선택형 이야기 생성 (발단 → 선택 4회 → 결말, 횟수는 설정값)
- 장면 조립 그림 + 캐릭터 상태 효과 애니메이션
- TTS 읽어주기
- 효과음·배경 음악
- 내 책장 (다시 보기·듣기), 이어하기
- 익명 사용 기록 수집
- PWA 설치

**제외 (이후 단계)**
- 구글 로그인
- 결말 그림 AI 생성
- 이야기 공유 링크
- 네이티브 앱

## 5. 화면 흐름

```
홈 ─→ 처음 선택 (주인공 → 성격 → 배경 → 사물) ─→ 이야기 읽기 ⇄ 선택지 고르기 (×선택 횟수) ─→ 결말 ─→ 완료
 └→ 내 책장 ─→ 저장된 이야기 다시 보기
```

| 화면 | 동작 |
|---|---|
| 홈 | "새 이야기 만들기", "내 책장" |
| 처음 선택 | 질문 하나에 카드 하나씩 고름. ① "이번 이야기의 주인공은 누구일까요?" 캐릭터 5장 ② "(주인공)은 한마디로 말하면..." 성격 4개 ③ "어디에서, 어떤 날 일어난 이야기일까요?" 장소·상황 4개 ④ "(주인공)이 가지고 있던 것은?" 사물 4개. "이전", "다시 뽑기" 버튼. 성격·상황은 그림 대신 이모지 |
| 이야기 읽기 | 한 페이지씩 넘김. 장면 그림 + 본문 + 자동 음성 재생 |
| 선택지 | 3개. 물건형은 그림 카드, 문장형은 글자 버튼(그림 없음). 글을 못 읽는 아이를 위해 선택지 읽어주기 필수 |
| 완료 | "다시 듣기", "새 이야기". 책장에 자동 저장 |

**생성 대기 화면**
- 로딩 바 없음. 마지막 페이지 장면이 캐릭터 상태 효과로 계속 움직임
- 목표 대기 시간 10초 이내. 15초 초과 시 "조금만 기다려줘" 음성 1회

## 6. 시스템 구조

| 구성 | 역할 |
|---|---|
| 프론트 (React + Vite + TS, PWA) | 화면, 장면 조립, 애니메이션, 음성·음악·효과음 재생 |
| 백엔드 (FastAPI, Cloud Run) | LLM·TTS 호출, 결과 검증, 저장, 사용 기록 |
| Supabase | DB (이야기, 사용 기록), Storage (TTS 음성 파일) |
| `catalog.json` | 그림·상태 효과·효과음·음악의 ID, 이름, 태그. 프론트와 백엔드가 같은 파일 사용 |

**백엔드 모듈**
| 모듈 | 역할 |
|---|---|
| `llm` | 기본 모델 호출, 실패 시 예비 모델로 전환 |
| `prompt` | 카드, 지난 내용 전체, 에셋 목록으로 프롬프트 조립 |
| `validator` | 형식 검사, 없는 ID 제거, 금지어 검사. 실패 시 1회 재생성 |
| `tts` | 구간 단위 음성 생성(Gemini TTS, 예비 Typecast), 사용량 집계, 목소리 결정 |
| `limiter` | 익명 ID별·전체 생성 한도 관리 |

**API**
| 메서드 | 경로 | 동작 |
|---|---|---|
| POST | `/stories` | 카드 받아 이야기 생성 시작, 발단 구간 반환 |
| POST | `/stories/{id}/next` | 선택 받아 다음 구간(또는 결말) 반환 |
| GET | `/stories?anon_id=` | 내 책장 목록 |
| GET | `/stories/{id}` | 저장된 이야기 전체 (다시 보기, 이어하기) |
| POST | `/events` | 사용 기록 |

**LLM 출력 형식 (구간 1회분)**
```json
{
  "pages": [
    {
      "text": "토끼는 장미 정원에 도착했어요...",
      "scene": {
        "background": "garden",
        "time": "night",
        "characters": [{ "id": "rabbit", "state": "surprised" }],
        "objects": ["rose"]
      },
      "mood": "mystery",
      "sfx": "magic_sparkle"
    }
  ],
  "choices": [{ "id": "dragon", "label": "작은 용" }]
}
```
- 캐릭터 위치는 프론트가 자동 배치
- 결말 구간은 `choices` 없음
- 모든 ID는 `catalog.json`에 있는 값만 허용

**데이터 흐름**
1. 카드 선택 → `POST /stories` → LLM(발단) → 검증 → TTS → 저장 → 응답
2. 선택 → `POST /stories/{id}/next` → 지난 내용 전체 + 선택 → LLM → 검증 → TTS → 저장 → 응답
3. 2를 반복. 마지막 선택(선택 횟수번째) 후에는 결말 생성 → 완료 처리
4. 내 책장 → 저장된 텍스트·음성 URL로 재생 (LLM·TTS 호출 없음)

## 7. 그림·소리

**장면 조립**
- 배경 위에 캐릭터·사물 조각 배치
- 낮/밤 등 시간대는 CSS 색 필터로 변형
- 반복 동작: 통통 튀기, 흔들림, 반짝임, 숨쉬기 (CSS 애니메이션)
- 같은 조각이 반복돼도 배치 위치·크기·시간대 변형으로 다양하게 보이게 함

**캐릭터 상태 효과** (캐릭터 그림과 별개로 겹쳐 표시)
| 상태 | 표시 |
|---|---|
| 말하기 | 입 옆 소리 표시 + 몸 들썩 |
| 잠자기 | 머리 위 'zzz' + 천천히 숨쉬기 |
| 놀람 | '!' + 통 튀기 |
| 기쁨 | 하트·반짝이 |
| 생각하기 | '...' 말풍선 |
| 그 외 | 무서움, 걷기 등. 총 10개 내외 |

**소리**
- 배경 음악: 분위기별 반복 재생. 결말에서 전용 음악으로 전환
- TTS 재생 중 배경 음악 볼륨 자동 감소
- 효과음: 페이지당 최대 1개
- 음소거 버튼 제공

**음성 (2026-10-29 갱신)**
- Gemini TTS 사용. Google Cloud TTS는 결제 계정 설정 부담으로 제외, Azure는 소리가 기계적이라 품질에서 탈락
- 무료 한도: TTS 모델마다 하루 10회, 분당 3회 (gemini-2.5-flash-preview-tts, gemini-3.1-flash-tts-preview, gemini-3.8-flash-tts, gemini-3.8-flash-lite-tts)
  - 페이지별이 아니라 **구간 단위**로 한 번에 생성 → 1편 = 선택 횟수 + 1회 (기본 5회)
  - 이야기마다 TTS 모델 하나를 정해 쓰면 모델 4개로 하루 약 8편
- 응답 1회 10~20초 → 아이가 선택지를 보는 동안 미리 생성해 대기 시간을 가림
- 구간 음성 하나에 여러 페이지가 들어가므로 페이지 넘김은 글자 수 비율로 맞춤
- 읽기 속도는 TTS 지시문 대신 재생 속도(`playbackRate`)로 조절, 앱 설정에서 저장 (지시문을 본문 앞에 붙이면 3.x 모델이 지시문까지 소리 내어 읽음)

**예비 TTS: Typecast**
- Gemini 하루 한도를 다 쓰면 Typecast 사용
- 무료 한도: 월 15,000자, 동시 호출 2개 → 1편 600~1,000자 기준 월 15~25편
- 무료 음성은 비상업 용도만, 출처 표기 필수 → 앱 화면(예: 완료 화면·정보 페이지)에 표기

**목소리 고정 규칙**
- 이야기 시작 시 아래 순서로 정함
  1. 오늘 남은 호출 수가 1편 분량(선택 횟수 + 1회) 이상인 Gemini TTS 모델
  2. 없으면 이번 달 남은 글자 수가 1편 분량(약 1,000자) 이상일 때 Typecast
  3. 둘 다 없으면 처음부터 브라우저 TTS
- 결정한 방식·모델·목소리를 `stories.voice`에 저장. 중간 변경 없음

## 8. DB (Supabase Postgres)

| 테이블 | 주요 컬럼 |
|---|---|
| `stories` | id, anon_id, cards, status(진행중/완료/실패), voice, choice_count, created_at, completed_at |
| `segments` | id, story_id, order, type(발단/중간/결말), chosen_choice, pages(JSON), choices(JSON), model_used, latency_ms |
| `events` | id, anon_id, story_id, type, payload(JSON), created_at |
| `usage_counters` | 날짜·월 단위 LLM 호출 수, TTS 모델별 호출 수(Gemini), TTS 글자 수(Typecast) |

- 음성 파일 경로: 구간당 1개 `stories/{story_id}/{segment}.wav`, URL은 `segments`에 기록. 페이지 넘김 시점은 글자 수 비율로 계산
- `events` 수집 항목: 카드 선택, 구간 생성 시간, 선택 소요 시간, 중도 이탈 지점, 완료, 다시 보기, 음소거, 오류

## 9. 오류 처리

| 상황 | 처리 |
|---|---|
| LLM 형식 오류·검증 실패 | 1회 재생성 → 예비 모델 → 실패 시 "다시 해볼까요?" 버튼 |
| LLM 한도 초과 | 예비 모델로 전환. 둘 다 초과 시 "오늘은 이야기 친구가 쉬어요" 안내 |
| 없는 에셋 ID | 해당 ID만 제거. 배경 없으면 기본 배경 |
| TTS 실패 (중간) | 같은 목소리로 해당 구간 재시도 → 실패 시 그 구간은 텍스트만 표시. 목소리 섞지 않음 |
| 네트워크 끊김 | 진행 상태 저장. 다시 열면 마지막 선택지부터 이어하기 |

## 10. 안전·비용 장치

**아이 대상 안전**
- 프롬프트 규칙: 폭력·공포·죽음·차별 금지, 4~7세 어휘, 짧은 문장, 따뜻한 결말
- 생성 후 금지어 검사 → 걸리면 재생성
- 자유 입력 없음 (카드·선택지만)
- 개인정보 수집 없음 (익명 ID만)

**비용 보호**
- 익명 ID당 하루 3편 (설정값)
- 전체 일일·월간 LLM 호출 수, TTS 호출 수·글자 수 상한. 도달 시 신규 생성 중단 또는 다음 TTS(Typecast → 브라우저 TTS)로 전환
- Cloud Run 최대 인스턴스 수 제한, GCP 예산 알림 (배포 단계에서 상세 정리)

## 11. 사전 실험 (개발 전, 버리는 코드)

| 항목 | 후보 | 통과 기준 |
|---|---|---|
| LLM | Gemma, Nemotron(OpenRouter), Gemini Flash 무료 티어 | 한국어 자연스러움, JSON 형식 준수율 90% 이상, 구간당 10초 이내, 하루 한도 확인 |
| TTS | Google Cloud TTS, Azure TTS → 실제 비교: Azure, Gemini TTS, Typecast | 한국어 동화 목소리 품질, 무료 한도, 응답 속도. 결과: 기본 Gemini TTS, 예비 Typecast (Google Cloud는 결제 설정 부담으로 제외, Azure는 품질 탈락) |

- LLM 품질 비교는 14장 "모델·프롬프트 평가" 방식 사용
- 결과: 기본·예비 LLM 1개씩, 기본·예비 TTS 1개씩 확정. 결과 문서로 남김

## 12. 에셋

| 종류 | 수량 (최종) | 최소 세트 | 방법 |
|---|---|---|---|
| 취향 카드 그림 | 25 | 10 | 로컬 이미지 생성. 캐릭터·사물 조각과 겸용 |
| 배경 | 15 | 5 | 로컬 이미지 생성 |
| 캐릭터·사물 조각 | 40~60 (카드 포함) | 20 | 로컬 이미지 생성 → 배경 제거 → WebP |
| 상태 효과 | 10 | 5 | SVG 또는 CSS 직접 제작 |
| 효과음 | 20 | 10 | Pixabay, Freesound(CC0) |
| 배경 음악 | 5 | 3 | Pixabay |

- 에셋은 프론트 정적 파일로 함께 배포 (예상 10MB 이하)
- 출처·라이선스 목록 파일 관리

**이미지 제작: 로컬 생성 (비용 0, 개수 제한 없음)**
- 도구: ComfyUI + FLUX.1 **schnell** 경량화(양자화) 버전. 개발 PC(RTX 4070 노트북 8GB)에서 실행
- 라이선스: schnell은 Apache 2.0 → 상업 이용 가능. FLUX.1 **dev**는 비상업이라 사용 금지
- 대안: SDXL 계열 그림체 모델 (모델별 라이선스 확인 필수)
- 보조: 웹 무료 서비스(Bing Image Creator, Leonardo 등)는 한도·약관이 자주 바뀌어 쓰기 직전 확인
- 화풍 통일: 공통 스타일 문구를 모든 프롬프트에 고정. 부족하면 LoRA로 화풍 고정
- 배경 제거: `rembg`로 일괄 처리
- 준비: 모델·부가 파일 약 10~20GB, 설치·설정 1~2시간
- 생성 도구는 제작용일 뿐 앱에는 포함되지 않음. 앱에는 완성된 그림 파일만 포함

**소리 제작: 무료 라이브러리 위주**
- 기본: Pixabay (상업 이용 가능, 출처 표기 불필요)
- 효과음 보충: Freesound (CC0만)
- 부족한 효과음만: Stable Audio Open 로컬 생성 (라이선스 조건 확인)
- 사용 금지: Suno 등 음악 생성 무료 플랜 (대부분 비상업 조건)

## 14. 평가·기록 (포트폴리오·발표용)

**모델·프롬프트 평가**
- 고정 카드 조합 10개 × 모델(또는 프롬프트 버전)별 1편씩 생성. 같은 회차에는 모든 대상에 같은 카드·선택 사용
- 심사: 웹 챗봇(ChatGPT, Gemini, Claude)에 직접 첨부해 수동 심사. 생성용 무료 모델보다 성능이 높고 심사용 API 한도가 필요 없음
  - 이야기 1편 = 파일 1개, 파일 이름은 익명(s01.md…)으로 모델을 숨김. 여러 파일을 한 번에 첨부
  - 평가 질문은 고정 파일(`평가질문.md`)을 매번 그대로 사용, 챗봇마다 새 대화창
  - 기준별 점수(합계 100): 어휘 20, 전개 20, 연결 25, 분량 10, 안전 15, 선택지 10. 결과는 CSV로 받아 저장
- 평균 점수로 비교. 사람이 일부 표본을 직접 읽고 심사 결과와 대조
- 무료 한도 때문에 생성은 며칠에 나눠 실행

**수치 지표**
| 지표 | 출처 |
|---|---|
| 형식 준수율, 재생성 비율 | `segments`, 서버 로그 |
| 구간 생성 시간 | `segments.latency_ms` |
| 오류율 (LLM, TTS) | `events` |
| 완료율, 중도 이탈 지점 | `events` |
| 심사 평균 점수 | 평가 결과 파일 |

**기록 파일**
| 파일 | 내용 |
|---|---|
| `prompts/` | 프롬프트 버전별 원문 (v1, v2…) |
| `prompt.md` | 최종 프롬프트 + 버전별 "무엇을, 왜 바꿨고, 점수가 어떻게 변했나" |
| `docs/troubleshooting.md` | 예상과 다른 출력·오류: 증상 → 원인 → 해결 → 결과. 바로 고치지 않고 먼저 기록 |
| `README.md` | 다른 사람이 그대로 실행 가능하게: 환경 변수 예시, 실행 명령, 에셋 출처 |

**설계 판단과 맞바꾼 것 (회고용)**
| 판단 | 얻은 것 | 포기한 것 |
|---|---|---|
| 실시간 이미지 생성 대신 조립 방식 | 비용 0, 화풍 일관성, 안전 | 그림 다양성 |
| 한 이야기 안 목소리 고정 | 몰입 유지 | 한도 부족 시 처음부터 음질 낮은 브라우저 TTS |
| Next.js 대신 React + FastAPI | 디버깅 쉬움, 익숙한 Python | 배포처 2개 |
| 임베딩 대신 ID 직접 선택 | 엉뚱한 매칭 방지, 단순함 | 에셋이 많아지면 프롬프트가 길어짐 |
| 로그인 없음 | 진입 장벽 낮음, 빠른 개발 | 기기 바꾸면 책장 유실 |

**한계와 다음 단계:** 유료 모델이면 실시간 이미지·효과음·음악 생성, 더 나은 이야기 가능. 영상화는 "책"이 아니라 "영상 시청"이 될 우려가 있어 신중히 검토

## 15. 개발 순서

1. 사전 실험 + 에셋 제작 환경(ComfyUI) 준비
2. 백엔드 이야기 생성 (LLM + 검증 + DB), 텍스트만
3. 프론트 기본 흐름 (카드 → 읽기 → 선택 → 결말), 텍스트만
4. 장면 조립 + 상태 효과 애니메이션
5. TTS + 효과음·음악
6. 내 책장 + 이어하기 + 사용 기록
7. PWA + 배포 + 비용 보호 설정
8. 지인 베타 → 수정 → 공개
9. 발표 자료 정리: 평가 리포트, 시연 영상(1~3분, 핵심 흐름 + 방어 장면)
